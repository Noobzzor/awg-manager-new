# Native runtime generation witness — feasibility, 2026-11-06

Existing parent Task3 requires ConfirmRunning to reject success inferred solely from files, ReloadNow, or controller availability. Two disposable controls outside the product tested configuration-derived SHA256 tags on the pinned real sing-box: an unused selector and an unused direct outbound. Both tags were visible in the running engine's Clash proxies API.

Observed controls: start A and confirm its tag plus real loopback HTTP200/body; write valid B to disk without applying and reject B despite HTTP200 from the controller while A still allows traffic; stop/start B and confirm B tag, retired A absence and an actual HTTP502 rejection; write an unstarted candidate and reject its tag despite the healthy B controller; restore A and confirm HTTP200/body. A connection error was not accepted as proof of BLOCK. The unstarted candidate was not separately passed to the native config checker; the proof is its absence from the running generation, not a new native validation result.

Technical ruling: prefer investigating an unused direct outbound over a selector witness, because the existing localCompositeTags function classifies selector/urltest/loadbalance objects as tunnel-like. Full original UI/catalog filtering is not proven by this spike. This is a generation witness candidate, not cryptographic attestation or a completed production ConfirmRunning callback.

Before integration: derive the witness from the entire final runtime input, including DNS/base/user/subscription slots, under the existing shared writer/runtime leases; avoid hashing the generated witness into itself. Reserve the namespace and reject supplied collisions. Bind confirmation to the owned process and intended controller/authentication, not an arbitrary healthy API or cached reply. Exclude the marker from editable outbounds/catalog/exports. Preserve journal before/after expectations, fail-closed errors and manual-stop intent. Recover before adoption/producers/GC and make config-root creation durable. Prove actual production restart/TUN and ownership handoff; these controls used mixed loopback ingress only and explicitly stopped/restarted their own process. Neither AWG/TUN nor VPS nor a failed native reload was tested.

No product code, editor capability, original frontend, VPS or frozen package changed. This record does not finish owner/runtime/startup integration or the parent plan.
