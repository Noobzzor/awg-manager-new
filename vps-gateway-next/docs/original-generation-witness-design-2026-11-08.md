# Runtime JSON generation construction and live witness

Parent Task3 extension following the two accepted native feasibility controls. Technical choices are delegated by the user. Reuse singbox.ClashClient and the original runtime, with an unused direct outbound; no new editor or routing model.

PrepareRuntimeGeneration accepts one final rendered JSON object, preserves numbers and all fields, hashes canonical JSON before appending one direct outbound named awgm-generation-<sha256>. Require an existing nonempty outbounds array so the witness cannot become the first implicit default. Reject malformed/trailing/duplicate JSON and reserved names or references. Equivalent object-key ordering produces one tag; changes in DNS, user, subscription, route or other JSON affect it. Never log configuration or error payloads. This is a digest of the supplied JSON, not proof of referenced file contents, remote rule-set data, or that the caller supplied the complete runtime input.

ClashClient.VerifyRuntimeGeneration uses a context-bound bounded request, not GetProxies' context-free convenience path. Accept only the exact requested generation with matching name/direct type and no competing reserved generation. Reject malformed/oversized/trailing responses, invalid tags, cancellation, HTTP and transport errors. No readiness/version/files-only fallback. The existing GetProxies behavior remains unchanged.

These independently testable production-package primitives will be exercised by a real-engine native test with DIRECT/BLOCK/DIRECT and disk-only/stale candidates. They do not themselves bind process identity, authenticate another controller, publish generation files, coordinate producers, prove immutable external assets, or implement SlotApplyBackend.ConfirmRunning. Those production integration requirements, exclusive ownership, startup recovery before adoption/GC, durable config-root creation and original UI/TUN acceptance remain open. No existing launch path or editor capability is enabled by this slice.
